## 使用约定

1. **任何规则改动前后都必须跑 `eval/run_eval.py`，并与本目录逐项对比**；不允许静默改基线数字。
2. 三项缺陷的修复任务见 `docs/issues/`，每条都写了改法与预期指标。
3. 修复后的结果另存 `eval/results/v2/`，并在论文/答辩中同时呈现 v1 → v2 的对照——这是「评测驱动迭代」的证据，不要只放修复后的漂亮数字。
4. 本基线中 `value_ladder_accuracy_vs_implementation = 100%` 与 `vs_intent = 80%` 的差值是关键：**用例按实现写会得到满分，按业务意图写才暴露问题**。后续新增用例一律按业务意图标注。
5. **E5 的 `ratio` 口径与运行时不一致**（评测有符号、后端取绝对值），因此「WITHIN 不可达 / 误升档 100%」不能直接当作线上故障引用。统一口径的方案见 `docs/issues/003-gas-within-unreachable.md`；在口径统一前，任何引用这条结论的论文或 PPT 都要加限定语。
