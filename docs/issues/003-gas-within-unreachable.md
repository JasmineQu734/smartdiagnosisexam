# [P1] 气体定档 `ratio` 存在两套口径，「WITHIN 不可达」结论不成立

- **编号**：ISSUE-003
- **状态**：待决策（先统一口径，再改规则）
- **严重度**：P1（影响论文与答辩中一条关键结论的可信度）
- **位置**：
  - 运行时：`backend/src/main/java/com/power/train/report/ReportAttributionService.java:167`（取绝对值）
  - 评测：`eval/adapters.py:170-185`（有符号，含 `-0.05` / `-0.40`）
  - 规则：`db/init/009_report_gas_rules.sql:50-57`

## 现象

同一个事实名 `ratio`，两处定义不同：

| 位置 | 定义 | 取值范围 |
|---|---|---|
| 运行时 | `abs(value − threshold) / threshold` | `[0, +∞)` |
| 离线评测 | `(value − threshold) / threshold` | `(−1, +∞)`，低于阈值为负 |

规则 `REPORT_GAS_WITHIN_NEAR` 的条件是：

```json
{"all":[{"fact":"over_threshold","op":"is_false"},{"fact":"ratio","op":"lte","value":0.10}]}
```

它只在「ratio 非负」的前提下才表示「余量 ≤10%」。一旦 ratio 为负（表示低于阈值），
`lte 0.10` 对所有低阈读数**恒真**，于是 WITHIN 永远轮不到。

## 两个口径下的结论完全相反

| 口径 | NEAR | WITHIN | 舒适读数（余量 >10%）误升档 |
|---|---|---|---|
| 运行时（非负） | 命中，余量 ≤10% | 命中，余量 >10% | 0 |
| 评测（有符号） | 命中，全部低阈读数 | **0 命中** | **100%（40/40）** |

因此必须更正一个说法：

> `eval/results/v1/tables.md` 里「REPORT_GAS_WITHIN 不可达 / 误升档 100%」**只在评测口径下成立**。
> 线上并未发生该故障——但它随时会因一次「把 ratio 改成有符号」的重构而出现，且没有任何测试守护。

## 根因

1. **事实口径由调用方定义，规则只写条件**：口径变了，规则不会被复核，也没有编译期约束。
2. **条件的前提没有声明**：`ratio <= 0.10` 隐含「ratio 非负」，但规则表、文档、注释里都没写。
3. **评测为覆盖「低阈」场景引入了有符号 ratio，没有同步后端**：这是典型的「同一场景两套事实口径」，
   正是 `AGENTS.md` 反复警告的那类坑。

## 修法：先选口径，再改规则（不要同时改）

### 方案 A（推荐）：统一为有符号

**后端**去掉绝对值：

```java
return value.subtract(threshold).divide(threshold, 4, RoundingMode.HALF_UP);
```

**规则**补下界（`-0.10 < ratio <= 0.10` 才算「接近阈值」）：

```json
{"all":[
  {"fact":"over_threshold","op":"is_false"},
  {"fact":"ratio","op":"gt","value":-0.10},
  {"fact":"ratio","op":"lte","value":0.10}
]}
```

`REPORT_GAS_WITHIN` 保持 `over_threshold is_false` 兜底，自然只接 `ratio <= -0.10`。

- 收益：能区分「低于阈值」与「超过阈值」，与评测阶梯语义一致，未来写「余量 30% 以上」这类规则不用再绕。
- 代价：`ratio` 的含义变化，需 grep 前端与文档；历史 `analysis` 已落库，不回溯。

### 方案 B（最小改动）：统一为非负

- 评测 `gas_grid` 的 `ratio` 改为绝对值，预期阶梯同步改。
- 规则不动，线上行为不变。
- 代价：丢掉方向信息；E5 的「不可达 / 误升档」指标归零，论文里这条结论要删掉。

**建议选 A**，并在同一批把「方向」显式写进规则，避免以后再靠符号猜。

## 验收

1. **新增阶梯连续性测试**（当前缺失，这是本条最重要的产出）：
   ratio 从 `-0.99` 到 `+0.99`，步进 `0.01`，断言每次**恰好命中一条** VALUE 组规则，且命中编号符合余量语义。
2. 线上联调：余量 30% 的报告 → `severity=低`；余量 5% 的报告 → `severity=中`。
3. 重跑评测：`E5.unreachable_rules == []`、`false_escalation_rate == 0.0`。
4. 重跑 `E2`，确定性仍为 100%。

## 风险

- **两处同时改会互相掩盖**：先定口径并加测试，再改规则条件。分两个提交，便于回滚。
- 若前端某处展示 `ratio`，符号变化会让文案变成负数，必须一起改（用 `abs` 展示，用有符号判定）。
- 历史报告的结论不回溯；如需一致，走已有 `POST /reports/{reportId}/analyze` 重跑。
